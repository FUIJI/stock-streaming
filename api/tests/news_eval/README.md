# ชุดทดสอบการให้คะแนนข่าว (Phase 3d · D3)

ข่าวจริง 30 ข่าวพร้อมคำตอบที่**คุณ**ติดป้ายไว้ ใช้วัดว่า AI ให้คะแนนตรงกับคนแค่ไหน
ต้องรันทุกครั้งที่แก้ prompt หรือเปลี่ยนโมเดล · ไม่รันใน CI เพราะใช้ API key และโควตาจริง

## 1. ดึงข่าวจาก VM
```bash
cd ~/docker/stock-streaming
docker compose -f docker-compose.prod.yml -f deploy/compose.vm.yml run --rm -T api \
  python -m src.news.export_eval --limit 30 > ~/cases.json
```
เลือกข่าวให้กระจายตามคะแนนที่ AI ให้อยู่ตอนนี้ (1–5) จะได้ไม่ได้ข่าวคล้ายกัน 30 ข่าว
ในไฟล์**ไม่มีคำตอบของ AI** เพื่อไม่ให้มีผลต่อการติดป้ายของคุณ

## 2. ติดป้าย (ใช้เวลาประมาณ 20–30 นาที)
แก้เฉพาะช่อง `label` ของแต่ละข่าว ช่องที่ไม่แน่ใจปล่อยเป็น `null` ได้ ช่องนั้นจะไม่ถูกนับ
```json
"label": {
  "importance": 4,
  "per_symbol": {"AAPL": {"sentiment": "-", "relevant": true}},
  "note": "ดาวน์เกรดจากโบรกใหญ่"
}
```

**`importance`** — ข่าวนี้สำคัญกับหุ้นที่ติดตามแค่ไหน
| คะแนน | ความหมาย | ตัวอย่าง |
|---|---|---|
| 5 | น่าจะทำให้ราคาขยับแรงทันที | งบต่างจากที่คาดมาก, ปรับ guidance, ควบรวมกิจการ, ถูกสอบสวน/ฟ้องใหญ่, CEO ลาออก |
| 4 | สำคัญกับบริษัทโดยตรง | อัปเกรด/ดาวน์เกรดจากโบรกใหญ่, เปิดตัวสินค้าหลัก, ได้/เสียสัญญาใหญ่ |
| 3 | เกี่ยวข้องแต่ไม่น่าขยับราคามาก | ข่าวอุตสาหกรรม, คู่แข่งเคลื่อนไหว, ความเห็นนักวิเคราะห์ทั่วไป |
| 2 | กล่าวถึงผ่าน ๆ | ข่าวสรุปตลาดที่มีชื่อบริษัท |
| 1 | แทบไม่เกี่ยว | listicle, แท็กหุ้นมาผิด |

**`sentiment`** (ต่อหุ้น) — ข่าวนี้ดีหรือร้ายต่อ**ราคาหุ้นตัวนั้น**
`"+"` ดี · `"-"` ร้าย · `"0"` กลาง ๆ หรือไม่มีผล

**`relevant`** (ต่อหุ้น) — ข่าวนี้**เป็นเรื่องของบริษัทนี้จริง**ไหม
`true` เป็นเรื่องของบริษัทนี้ · `false` แค่ถูกพูดถึงหรือแท็กมาเฉย ๆ

ตัดสินจากหัวข่าวและ summary ในไฟล์เท่านั้น เพราะ AI เห็นแค่นั้นเหมือนกัน

## 3. เก็บเข้า repo
คัดลอกไฟล์ที่ติดป้ายแล้วมาไว้ที่ `api/tests/news_eval/cases.json` แล้ว commit ชุดทดสอบจะได้ไม่หายและเทียบผลข้ามเวอร์ชัน prompt ได้

## 4. รัน eval
```bash
docker compose -f docker-compose.prod.yml -f deploy/compose.vm.yml run --rm -T api \
  python -m src.news.eval --runs 2 < ~/cases.json
```
- ใช้ประมาณ 2 call ต่อรอบ (ชุดละ `LLM_TRIAGE_BATCH` ข่าว) · `--runs 2` รัน 2 รอบเพื่อดูว่า AI ตอบเหมือนเดิมไหม
- วัดเฉพาะโมเดลหลัก (Gemma) และเว้น 1 นาทีต่อ call (`--rpm 1`) เพราะ API ที่รันอยู่ใช้ key เดียวกัน และ Gemma ฟรีได้แค่ 16K token/นาที · ใส่ `--with-fallback` ถ้าอยากรวม Flash (โควตา 20 ครั้ง/วัน)
- เจอ `! N articles: Gemini 429` = ชนเพดานต่อนาทีของ Google · รอ 1–2 นาทีแล้วรันใหม่ · อย่ารัน eval หลายตัวพร้อมกัน
- **เกณฑ์ผ่านก่อนไป D4:** importance ต่างไม่เกิน ±1 อย่างน้อย 85% และทิศของ sentiment ตรงอย่างน้อย 80%
- รายการ `✗` คือข้อที่ AI ตอบไม่ตรงกับป้าย บางข้ออาจเป็นป้ายที่ควรแก้ ไม่ได้แปลว่า AI ผิดเสมอ
